# Configurar Codex en cada copia

1. Usa Codex actualizado con Git y Python 3.11 o posterior en el PATH. El punto de referencia para este entorno es la CLI 0.169.0. En Windows, usa WSL para la configuración y los comandos POSIX del hook. En ese caso instala los requisitos dentro de la distribución.
2. Abre la raíz del repositorio en la app o ejecuta `codex` desde la raíz. Identifica el repositorio y revisa `.codex/config.toml`, `.codex/hooks.json` y el script que ejecuta el hook. Confía en el proyecto en el cliente. Los ajustes de proyecto se cargan solo en una capa confiable. [Capas y confianza](https://learn.chatgpt.com/docs/config-file/config-basic).
3. En la CLI, abre `/hooks` y revisa la definición local antes de confiar en ella. Codex registra confianza por definición. Tras actualizar la rama revisa también el script invocado, aunque la definición siga igual. [Descubrimiento y confianza de hooks](https://learn.chatgpt.com/docs/hooks#review-and-trust-hooks).
4. Comprueba `/status` y `/skills`. Deben aparecer `new-feature`, `code-review`, `merge-feature` y `humanizer`; escribe `$` para elegir una skill local. Para comprobar un agente, pide a Codex que abra `reviewer` y le encargue leer `AGENTS.md` y resumir el flujo en español. En la CLI usa `/agents` o `/subagents` para ver las sesiones auxiliares. [Skills](https://learn.chatgpt.com/docs/build-skills), [Subagentes](https://learn.chatgpt.com/docs/agent-configuration/subagents).
5. Para acciones remotas, usa tu cuenta de GitHub en el navegador o autentica `gh` con `gh auth login` en la terminal y verifica `gh auth status`. Coordina con A la configuración de [ramas y permisos](collaboration.md). La confianza de Codex y la autenticación son decisiones de cada persona.

## Pedir una revisión en GitHub

1. En [Code Review de Codex](https://chatgpt.com/settings/code-review), inicia sesión con la cuenta que usará la integración. Conecta GitHub si falta la conexión y selecciona `DanielHermosilla/codex-hackathon` en la instalación de la app. Un administrador puede conceder acceso solo a ese repositorio privado.
2. Busca el repositorio en Code Review y comprueba que la revisión esté habilitada. Para el flujo manual, elige la modalidad que sigue las preferencias personales y deja apagada la revisión automática de tu cuenta.
3. En un PR abierto en GitHub, escribe `@codex review` como comentario independiente. Comprueba que Codex reaccione con 👀 y publique su revisión para ese PR. Si no reacciona, revisa la conexión, el acceso al repositorio y que Code Review esté habilitado.

Codex sigue las reglas de revisión de [AGENTS.md](../AGENTS.md). El equipo sigue usando CI y la aprobación de otra persona antes de integrar. [Documentación oficial de OpenAI](https://learn.chatgpt.com/docs/third-party/github).

## Configuración efectiva y diagnóstico

`.codex/config.toml` permite escritura en el espacio de trabajo y las carpetas temporales del sistema. Habilita la red saliente para consultar GitHub y descargar dependencias. El perfil `workspace-write` permite lectura fuera del repositorio. Codex envía las escalaciones compatibles a `auto_review`, que puede aprobarlas o rechazarlas. Git puede necesitar esa revisión para escribir sus metadatos incluso dentro del proyecto. Las confirmaciones del equipo para commit, push, publicación de PR e integración siguen el [flujo de colaboración](collaboration.md). Las exigencias administradas, las opciones del cliente y de la sesión y la confianza del proyecto influyen en la configuración efectiva. [Referencia](https://learn.chatgpt.com/docs/config-file/config-reference), [Revisión automática](https://learn.chatgpt.com/docs/sandboxing/auto-review).

Cada sesión admite hasta seis subagentes concurrentes además del principal. Ese límite controla cuántos subagentes se pueden abrir. La CPU, la RAM, la GPU y el paralelismo de compilación dependen del sistema y de las herramientas del motor.

Si faltan los ajustes o las skills, comprueba la carpeta con `git rev-parse --show-toplevel`, el estado de confianza y la versión del cliente. Abre una sesión nueva desde la raíz. En un worktree comprueba que los archivos están presentes y que la sesión apunta a ese checkout. Si hay skills homónimas, elige la ruta del repositorio. Usa `/status` para permisos y `/hooks` para estado y origen del hook. [Comandos de la CLI](https://learn.chatgpt.com/docs/developer-commands?surface=cli), [Worktrees](https://learn.chatgpt.com/docs/environments/git-worktrees).

Para un diagnóstico sin turno de modelo, la CLI 0.169.0 ofrece `codex app-server --strict-config --print-startup-config`. Su salida son requisitos de arranque. Para inspeccionar las capas efectivas, el método de App Server `config/read` admite `includeLayers: true` y `cwd`. Contrasta las claves de configuración con el esquema de la versión del cliente antes de actualizar. [Protocolo App Server](https://learn.chatgpt.com/docs/app-server), [Esquema oficial](https://github.com/openai/codex/blob/main/codex-rs/core/config.schema.json).

## Alcance de los controles

- Los especialistas heredan los permisos de la sesión. `reviewer` y `integrator` tienen instrucciones de solo lectura y `tester` ejecuta verificaciones acordadas. Las instrucciones orientan su conducta. La política de sandbox pertenece a la sesión principal. Usa el flujo de la skill si el cliente no permite abrir subagentes.
- El hook síncrono `PreToolUse` devuelve una denegación para operaciones Git directas reconocibles en `Bash`. Atiende commits y otras escrituras de historia en `main`, y pushes con destinos o banderas de riesgo. Para publicar una rama usa un refspec explícito como `git push -u origin feature/pausa:refs/heads/feature/pausa`.
- El alcance es el checkout y las formas directas de Git que reconoce el analizador. Quedan fuera los aliases, scripts, conectores, terminales externos y construcciones complejas del shell. Los errores del lanzador, los timeouts y un hook sin confianza pueden dejar que Codex siga adelante. GitHub es la autoridad remota. El hook tampoco inspecciona secretos ni ejecuta la suite por cada cambio. [Contrato de PreToolUse](https://learn.chatgpt.com/docs/hooks#pretooluse).
- Los worktrees comparten metadatos Git. Codex Desktop puede preparar el espacio de una tarea. Desde la CLI decide caso por caso y comprueba que el worktree usa la base esperada. Para revisar un PR en un checkout ocupado, `$merge-feature` admite validar un worktree separado fijado al SHA revisado.
